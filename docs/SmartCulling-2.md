## 2. История с группами
Основа для п. 3–4. Сейчас `history: [HistoryEntry]`.

```swift
enum HistoryItem {
    case file(HistoryEntry)
    case group([HistoryEntry], label: String)   // массовое: «23 кадра»
}
```
- `finishMove` разделить: внутренняя `recordMove(...) -> HistoryEntry` (переносит файлы, evict, `moveAnnotations`, `AnalysisStore.moveRecord`, удаляет из `allPhotos`) и внешняя часть (rebuildVisible, repairCompare, тост, prefetch). Одиночный перенос = recordMove + внешняя часть; массовый = N × recordMove + **один** rebuildVisible/тост/prefetch в конце.
- `undo()`: тело восстановления одного `HistoryEntry` вынести в `restore(_:) throws -> URL`. Для `.group` — восстанавливать **в обратном порядке**, вставляя в `allPhotos` по `allIndexBefore` (обратный порядок сохраняет правильные индексы), затем один `rebuildVisible(keeping: первый восстановленный)`, тост «Отмена · 23 кадра».
- Ошибка посередине массового удаления: то, что уже ушло в корзину, вернуть (как в `trashCurrent`), историю не записывать, показать `errorMessage`.
- Ошибка посередине группового undo: восстановленное остаётся, невосстановленное — обратно в историю как `.group` из оставшихся, ошибка в `errorMessage`.
- Заодно: в `restore` добавить `ThumbnailLoader.evict(entry.currentURL)` (сейчас только `ImageLoader.evict`).
- `trashCurrent` переписать через общую функцию `trashFrame(_ url: URL) throws -> HistoryEntry` — она же используется в массовых действиях.

**Чек‑лист:** одиночные перенос/корзина/Z работают как раньше (включая пары, сравнение, рисование — Z там отменяет штрих).

## 4. Массовые действия

### 4.1 «Брак»: «Всё в корзину…»
- Кнопка в верхней панели сетки, видна только в разделе «Брак» и только когда в нём есть кадры. Текст «В корзину все…», значок `trash`.
- Действует на **видимые сейчас** кадры раздела (с учётом выбранного чипа из п. 5). Если есть выделение (`selection`), то только на выделенные — и текст кнопки «В корзину выбранные (N)…».
- Подтверждение п. 3 → одна группа в истории → тост «В корзину · 23 кадра» (`.trash`).
- Клавиши нет (осознанно — опасное действие только кнопкой). Пункт в меню «Отбор»: «Отправить брак в корзину…».

### 4.2 «Серии»: оставить лучший
- **⇧Delete** (keyCode 51/117 + `.shift`; сейчас Shift в этом месте не обрабатывается — проверить в Grid и Viewer) и кнопка `Оставить лучший…` в заголовке серии.
- Действует на серию текущего кадра: всё, кроме `best`, в корзину. Подтверждение: «Оставить лучший кадр и отправить 7 в корзину?».
- Работает в сетке «Серий» (и в открытой серии) и в просмотре, если кадр из раздела «Серии». В «Все фото» — не работает (там серий не видно).
- После: серия из 1 кадра исчезает из раздела (уже так); текущим становится первый кадр следующей серии.

### 4.3 «Серии»: выбрать лучший вручную
- Клавиша **B** (keyCode 11, свободна в Grid/Viewer/Compare) и пункт «Сделать лучшим» в контекстном меню.
- Хранение: `AnalysisStore.bestOverride: [URL: URL]` — ключ = любой кадр серии? Ненадёжно: состав серий меняется. Проще: `manualBest: Set<URL>` (стандартизованные пути, сохранять как `labels`). В `refreshDefects` при выборе лучшего: если среди `members` есть кадр из `manualBest` — он лучший (если таких несколько — последний отмеченный; хранить с датой или порядком). При отметке нового — снять отметку с остальных кадров этой серии.
- `moveRecord` переносит и `manualBest`.
- Тост: «Лучший в серии» (`.done`). Подсказка у значка: «Выбран вручную».
- Z не отменяет (не действие с файлом); повторное B по другому кадру — и есть отмена.

### 4.4 «Во всех сериях оставить лучшие…» — **не делаем сейчас**
Только когда выбор лучшего проверен на реальных папках. Оставить пункт в плане.

**Чек‑лист п. 4:** 20 кадров брака с парами → в корзине 40 файлов, один Z вернул всё под прежними именами и на прежние места в «Все фото»; ⇧Delete в серии из 8 → остался 1, серия исчезла из раздела, Z вернул 7 и серия снова видна с тем же лучшим; B на другом кадре → значок переехал, ⇧Delete теперь оставляет его; Esc на подтверждении ничего не делает.

## 5. «Брак»: чипы причин, сортировка, значки

### 5.1 Чипы
- Строка под верхней панелью, только в разделе «Брак»: `Все 37 · Размыто 18 · Мягче соседей 6 · Глаза 6 · Пересвет 4 · Темно 3 · Горизонт 5 · Случайные 1 · Вручную 2`.
- Кадр с несколькими причинами входит в каждый подходящий чип. Чипы с нулём не показываем. В режиме модели (`learned`) чип причины = причины правил с уверенностью ≥ порога, плюс «Модель» для кадров, где правила молчат.
- Состояние: `PhotoSection.defects(reason: DefectReason?)` **или** отдельное `defectFilter: DefectReason?` в сессии — выбрать второе, чтобы не трогать `Equatable`/переключатель. Смена чипа = `rebuildVisible(keeping: currentPhoto, ...)`.
- Клавиатура не нужна (мышь достаточно; не нагружаем UX).
- Компонент: переиспользовать `PCSegmented`, если влезет по ширине, иначе горизонтальный ряд кнопок `PCButtonStyle(kind: .ghost)` с выделением выбранного; при нехватке места — горизонтальная прокрутка.

### 5.2 Сортировка
- Справа в строке чипов: `По времени · По уверенности` (`@AppStorage("defectSort")`, по умолчанию **по времени** — как сейчас сделано, пользователь не возражал).
- «По уверенности»: максимум `confidence` по причинам (в режиме модели — `probabilities[url]`), по убыванию; при равенстве — по времени.

### 5.3 Значки причин на миниатюрах
- В разделе «Брак» в углу ячейки — до 2 значков главных причин (SF Symbols), остальное в подсказке. В «Все фото» оставить текущий ⚠︎.
- Добавить в `DefectReason` `var symbol: String` и `var shortTitle: String` (для чипов). Кандидаты: blur `camera.metering.unknown`/`circle.dotted`, softer `circle.lefthalf.filled`, eyesClosed `eye.slash`, overexposed `sun.max.fill`, underexposed `moon.fill`, tilted `level`, accidental `hand.raised`, learned `brain`, manual `hand.point.up.left`. Проверить, что символы есть в SF Symbols под macOS 26.

**Чек‑лист п. 5:** все 4 темы светлые/тёмные; чип «Глаза» → в просмотре листание только по этим кадрам; удаление последнего кадра чипа → чип исчезает, фильтр сбрасывается на «Все».
