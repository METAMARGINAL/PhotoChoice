- Съёмка — **люди: портреты, события; Fuji JPEG (DSCF…)**.

## 1. Диагноз (по `docs/PhotoChoice-калибровка.csv`, 130 кадров, анализатор v5)

Ручной разметки в CSV нет (`label` пустой), выводы — по метрикам, но они однозначные.

| | Помечены «Размыто» (25) | Остальные (105) |
|---|---|---|
| `detail_ratio` (объект, копия 1280 px) — **по нему решает правило** | 0.286 | 0.394 |
| `full_detail` (фрагмент 512×512 в полном разрешении у глаз) | **0.824** | 0.753 |
| `full_sharpness` | **87** | 71 |
| `face_quality` (Vision) | **0.331** | 0.278 |
| есть лица | 24 из 25 | — |

Выводы:
1. **Правило «Размыто» смотрит не на ту метрику.** Корреляция `detail_ratio` (1280 px) с `full_detail` (100 % у глаз) ≈ **−0.03**: они никак не связаны. Помеченные кадры в полном разрешении в среднем *резче* остальных, и Vision оценивает их лица *выше*. Из 25 помеченных только **2** попадают в нижнюю четверть по `full_detail`.
2. Почему так: 24 из 25 — кадры с лицами. На копии 1280 px область объекта у портрета — это гладкая кожа и боке, мелких деталей мало по природе, а не из-за смаза. Плюс шумодав Fuji JPEG сглаживает текстуру. Метрика «доля мелких деталей» на портрете меряет кожу, а не фокус.
3. 25 из 130 (19 %) «размытых» — нереалистично для портретной съёмки на Fuji; реальный брак по резкости обычно единицы процентов.
4. Глаза: `eyes_min` 10‑й перцентиль ≈ 0.09–0.14 при пороге 0.10 — на границе; у мелких лиц на событиях (до 13 лиц в кадре) контур глаза по landmarks шумный. Это следующий источник ложных пометок, когда «Размыто» починим.

**Значит, первым делом чинить измерение и логику, а модель — вторым слоем.** Модель поверх неправильной метрики хаос не уберёт.

| Create ML классификатор на кропах глаз/лиц | обучение на своих кадрах, < 1 МБ | быстро | своё | Позже, если пользователь разметит ≥ 50 + 50 кропов |
| VLM (Qwen‑VL и т. п.) | объяснения словами | ГБ, секунды на кадр | — | Исключено бюджетом |

**MobileCLIP — почему подходит:**
- Текстовый энкодер в приложение **не кладём**: эмбеддинги промптов считаются один раз офлайн (Python) и лежат в бандле как JSON/бинарь. В приложении только image encoder.
- Одна модель закрывает три задачи: резкость/смаз, глаза, серии.
- Модель видит ~256 px, поэтому тонкий промах фокуса на всём кадре она не увидит. Решение: **подавать ей кроп лица/глаз из полного разрешения** (тот же 512×512 фрагмент, что уже декодируется для `fullDetail`) — тогда 256 px кропа = почти 100 % масштаб.

Скачивание: Hugging Face `apple/coreml-mobileclip` (готовые `.mlpackage`). Проверить при подключении: точный размер входа (256×256 у S0/S2?), нормализацию, выход (эмбеддинг 512, нормировать L2). Начать с **S2**; если анализ не укладывается в бюджет — S0.

## 3. Новая логика решений

### 3.1 Принципы
1. **Два независимых сигнала.** Кадр попадает в «Брак» по причине, только если с ней согласны ≥ 2 разных источника (классическая метрика + модель), **или** один источник в крайнем значении (уверенность ≥ 0.9). Это основное средство против хаоса.
2. **Сравнение, а не абсолют.** Резкость кадра сравнивается с соседями по серии и с перцентилем папки, а не с одной константой (у разных объективов, ISO и шумодава шкала разная).
3. **Портрет — значит, глаза.** Если есть крупное лицо, резкость оценивается **только** в области глаз в полном разрешении. Объект/салиентность — только для кадров без лиц.
4. **Ручная разметка главнее всего** (`docs/SmartCulling-2.md`, п. 1).
5. Каждое срабатывание объяснимо: в `detail` пишем оба сигнала («Глаза не в фокусе: детали 31 % от лучшего в серии · модель: размыто 0.82»).

### 3.2 Размыто (`blur`)
Сигналы:
- **S1 — классика:** `fullDetail` (с лицами — у глаз крупнейшего лица; без лиц — центр объекта) в перцентиле папки и относительно лучшего соседа по серии (`rel_detail`).
- **S2 — модель на кропе:** zero‑shot `p_blur_face` = softmax по парам промптов (см. 3.5) на кропе глаз/лица из полного разрешения; без лиц — на кропе объекта.
- **S3 — модель на кадре:** `p_motion_frame` — смаз всего кадра (движение камеры).

Решение (стартовое, подбирается на прототипе, этап B):
- уверенность = среднее нормированных S1 и S2, если оба выше своих порогов; иначе 0, **кроме** S1 или S2 ≥ 0.9 и S3 ≥ 0.7 (явный смаз всего кадра);
- старая метрика `detail_ratio` на 1280 px **больше не решает** — остаётся только в отладке/CSV.

### 3.3 Закрыты глаза (`eyesClosed`)
- Только крупные фронтальные лица (как сейчас).
- **S1 — landmarks** (текущая открытость), **S2 — модель** на кропе каждого глаза‑пары: `p_closed` по промптам «closed eyes / blinking» против «open eyes looking».
- Решение: закрыты, если S2 ≥ порога **и** S1 ниже порога; либо S2 ≥ 0.9.
- Лицо меньше ~120 px по ширине в исходнике — не оцениваем совсем (на событиях это основной шум).

### 3.4 Остальные причины
- **Пересвет / темно** — оставить классические (`clipWhite`, яркость лица), они работают; модель не нужна.
- **Горизонт** — без изменений.
- **Случайный кадр** — добавить zero‑shot на кадре («photo taken by accident, blurry floor, inside of a bag» vs «intentional photo»), решение — вместе с `isUtility`/эстетикой.

### 3.5 Промпты (стартовый набор, подбирается на прототипе)
Пары антонимов, как в CLIP‑IQA; на каждую сторону 2–4 формулировки, эмбеддинги усредняются.
- резкость лица: «a sharp, in‑focus close‑up photo of a face with crisp eyelashes» / «a blurry, out‑of‑focus photo of a face», «a face with motion blur»;
- смаз кадра: «a sharp photo» / «a photo with camera shake motion blur»;
- глаза: «a person with open eyes» / «a person with closed eyes, blinking»;
- случайный кадр: «a deliberate photograph of people» / «an accidental photo of the floor», «a dark blurry accidental shot».
Температура softmax — как у CLIP (logit scale из модели; проверить).

### 3.6 Обучение на разметке (существующая `DefectModel`)
Оставить логистическую регрессию, но признаки заменить на **компактные и устойчивые**: S1/S2/S3 по каждой причине, относительные к серии величины, качество лица. **Не** подавать 512‑мерный эмбеддинг, пока разметки < 200 кадров (переобучится). Модель включается только при ≥ 30 + 30 размеченных кадров и только если на отложенной части она точнее правил (показывать это в панели калибровки).

## 4. Серии
- Похожесть: **косинусное расстояние эмбеддингов MobileCLIP кадра** вместо Vision feature print (лучше держит «та же сцена, чуть другая поза»), плюс время (`seriesGap`) и раскладка лиц (как сейчас).
- Дрейф: в цепочке > 10 кадров сравнивать новый кадр и с первым (см. `SmartCulling-2.md` §6).
- Лучший кадр (`SeriesGrouping.best`): к текущим весам добавить `1 − p_blur_face` и `1 − p_closed` по каждому сопоставленному лицу; веса стартовые: резкость у глаз (S1+S2) 0.4 · глаза 0.3 · качество лиц 0.1 · эстетика 0.1 · экспозиция 0.1.
- Пороги серий подобрать по CSV (`gap_prev_s`, `print_dist_prev` + новая колонка `clip_dist_prev`).

## 6. Как проверяем (без большой разметки)
- **Набор для оценки:** 1–2 папки пользователя, ~150 кадров. Разметить **только помеченные** анализом кадры («брак/норма») — это 20–40 кликов, а не 300, и этого хватает, чтобы мерить главное — ложные пометки. Плюс 10–15 заведомо смазанных/моргнувших кадров, чтобы видеть, что брак не потерялся.
- **Метрики:** точность пометок при «Обычно» (доля настоящего брака среди помеченных) — цель **≥ 85 %**; ложных пометок — **≤ 2 на 100 хороших кадров**; явный смаз/моргание находится в ≥ 80 % случаев.
- **Прототип до Swift (этап B):** пользователь кладёт папку (или 30–50 кадров) в доступное место → Python‑скрипт `tools/eval.py` (open‑source MobileCLIP + те же кропы) считает S2 для промптов, сводит с CSV калибровки и показывает, при каких порогах/промптах точность максимальна. Только после этого переносим промпты и пороги в Swift. Это быстрее, чем подбирать в приложении.

## 9. Как сделано (2026-10-10)

**A. «Размыто» без модели.** CSV показал, что `full_detail` на Fuji JPEG меряет шум и шумодав (с качеством лица Vision корреляция −0.19), а `full_sharpness` (дисперсия лапласиана фрагмента 512 px в 100 %) — фокус (+0.41). Правило: `доля = fullSharpness / медиана fullSharpness папки` (`FolderStats.medianFullSharpness`, от 8 кадров), брак ниже `blurShare = 0.35`, уверенность `0.6 + 1.5 · (порог − доля)`, до 0.9; выдержка ≥ 1/4 с пропускается. `detail_ratio` 1280 px и флажок «сравнивать с резкостью по папке» убраны из решения (остались в отладке и CSV). Сохранённые пороги калибровки сбрасываются (новое поле). Мелкие лица для глаз — на этапе D.

**B → калибровка в приложении.** Из этой среды недоступны Hugging Face и PyPI, поэтому Python-прототипа нет. Вместо него в кэше хранятся векторы, а не вероятности: подсказки и пороги подбираются прямо в панели «Калибровка брака» (графики оценок модели рядом с разметкой) и по CSV (`p_blur`, `p_motion`, `p_closed_max`, `p_accidental`, `clip_dist_prev`). Векторы подсказок считает приложение: текстовую часть модели (`mobileclip_s2_text.mlpackage`, в бандл не входит) пользователь выбирает один раз, токенизатор — `CLIPTokenizer.swift` + `Models/clip-merges.txt` (словарь строится из списка слияний, сверено с эталоном simple_tokenizer). Результат — `Application Support/PhotoChoice/prompts.json` (главнее файла в бандле); кнопкой «Сохранить prompts.json…» его можно положить в `PhotoChoice/Models/`. `tools/prompts.py` не нужен.

**C. Анализатор v7.**
- Модель: `PhotoChoice/Models/mobileclip_s2_image.mlpackage` (путь из §5.1 изменён), грузится по URL (`COREML_CODEGEN_LANGUAGE = None`), `computeUnits = .all`, прогоны под замком одним пакетом на кадр. Нет пакета или выключена настройка `qualityModelEnabled` — анализ как в v6.
- Полное разрешение декодируется один раз и сразу развёрнутым (миниатюра без предела размера с `WithTransform`, `ShouldCacheImmediately`), `unorient` больше не нужен; из него — фрагмент 512 px для резкости и вырезки для модели.
- Векторы (Float16 через vImage, ≈1 КБ каждый; тип `Float16` недоступен на Intel): `clipFrame` — центральный квадрат копии 1280 px, `clipFocus` — фрагмент 512 px у точки фокуса, `FaceMetrics.clip` — до трёх крупнейших лиц шире 120 px в исходнике (квадрат ×1.4 вокруг лица из полного разрешения). `clipModel` — какой моделью посчитано; при включённой модели записи без него пересчитываются.
- Оценки (`ModelSignals`) считаются из векторов на лету при каждой пересборке: `blur` — вырезка крупнейшего лица (`faceBlur`), без лиц — фрагмент объекта (`objectBlur`); `motion` и `accidental` — кадр; `closed` — по каждому лицу (`eyes`). p = σ(100 · (cos(брак) − cos(норма))), на сторону 2–3 формулировки, векторы усредняются.
- Видно: отладочные строки в сведениях (`⌘I`, Debug), графики в калибровке («Модель MobileCLIP»), CSV, статус в настройках. **В решения о браке оценки пока не входят** — это этап D, после просмотра распределений на размеченных папках.
